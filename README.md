# Sitecore Content Transfer Utilities

This repository contains a small set of utilities and examples for
working with **SitecoreAI content migration and transfer workflows**,
particularly the Content Transfer API, Item Transfer API, and RAIF
files.

The tools are intended for Sitecore architects and engineers to use
directly, adapt for customer-specific requirements, or provide as
working examples when designing migration and environment-refresh
processes.

> These are implementation utilities and examples, not replacements for
> Sitecore's supported APIs or official migration guidance. Review and
> test them against the customer's environment, content model, security
> requirements, and deployment process before production use.

## Tools

  -----------------------------------------------------------------------
  Tool                                Intended use
  ----------------------------------- -----------------------------------
  **InspectRaif**                     Inspect and troubleshoot the
                                      contents of a RAIF file.

  **PackageToRaif**                   Convert a legacy Sitecore Package
                                      Designer ZIP package into RAIF for
                                      Item Transfer workflows.

  **ContentRefresh / Postman**        Learn, demonstrate, troubleshoot,
                                      or manually execute the Content
                                      Transfer and Item Transfer API
                                      workflow.

  **ContentRefresh / PowerShell**     Automate SitecoreAI-to-SitecoreAI
                                      content refreshes, primarily for
                                      CI/CD and lower-environment
                                      synchronization.
  -----------------------------------------------------------------------

Each tool directory contains its own `README.md` with detailed setup,
parameters, and usage instructions.

## InspectRaif

`InspectRaif.ps1` reads a RAIF file and produces a human-readable
manifest of its contents, with optional JSON export.

### Use it for

-   Verifying what a RAIF contains before transfer.
-   Troubleshooting content-transfer problems.
-   Inspecting item IDs, parents, templates, fields, languages,
    versions, and media/blob information.
-   QA of RAIF files generated by other tools, including
    `PackageToRaif`.

### Limitations

`InspectRaif` is an **inspection tool only**. It does not validate that
the destination environment can successfully consume the file, modify
the RAIF, resolve dependencies, or transfer content.

See `InspectRaif/README.md` for usage details.

## PackageToRaif

`Convert-SitecorePackageToRaif.ps1` converts a legacy **Sitecore Package
Designer ZIP package** into a RAIF file that can be consumed through
Sitecore's Item Transfer tooling.

This is primarily a bridge between legacy XM/XP package-based content
exports and SitecoreAI's RAIF-based transfer workflow. It also supports
media items and their packaged binary blobs.

### Use it for

-   Moving selected legacy XM/XP content into a RAIF-based migration
    workflow.
-   Converting existing Package Designer exports.
-   Migrating package content, including media, where another migration
    path does not support the required content.

### Limitations

This is a **format translator**, not a migration dependency engine.

It converts what is present in the package. It does not connect to the
source Sitecore instance to discover missing parents, templates,
referenced items, datasources, or other dependencies. Ordinary GUID
field values are not recursively interpreted as migration dependencies.

Successful RAIF generation means the package was successfully translated
and serialized; it does not guarantee successful import into a
particular destination.

See `PackageToRaif/README.md` for usage details.

## ContentRefresh

ContentRefresh provides two implementations of the same general
SitecoreAI content-transfer workflow for different purposes.

Sitecore's Content Transfer API handles the **source-to-destination
transfer and creation of RAIF files**. The Item Transfer API then
consumes those RAIF files into the destination database.

### Postman

The Postman collection and environment are intended for **manual,
one-off, educational, and troubleshooting use**.

The collection walks through the Content Transfer and Item Transfer APIs
step by step so an engineer can see the requests, responses, IDs,
chunk-transfer process, RAIF creation, and final item-transfer
operation.

Use it as:

-   A training/demo resource.
-   A reference implementation while learning the APIs.
-   A troubleshooting tool for executing individual API operations
    manually.
-   A starting point for customer-specific API experimentation.

It is deliberately procedural and manual; it is **not intended to be the
production automation mechanism** for recurring environment refreshes.

See the README in the ContentRefresh Postman directory for setup and
environment-variable requirements.

### PowerShell

The ContentRefresh PowerShell implementation automates the end-to-end
process of moving selected content from one SitecoreAI environment to
another.

Its primary intended use is **CI/CD and deployment automation**,
particularly refreshing or synchronizing lower environments from
production.

The provided implementation uses an inclusion-based manifest so the
content being transferred is explicitly defined. It is designed for
controlled downward synchronization and should be adapted to each
customer's environment topology and deployment requirements.

### Limitations

ContentRefresh is not a general-purpose database synchronization or
backup/restore system.

-   Only content included by the configured transfer scope is moved.
-   Parent chains and other required dependencies must be accounted for
    when defining transfer scope.
-   Destination behavior depends on the selected merge strategy.
-   `OverrideExistingTree` can delete destination descendants and
    therefore requires particular care.
-   Authentication, environment credentials, permissions, and CI/CD
    secret management remain the responsibility of the implementation
    using the tools.
-   The supplied automation should be reviewed and adapted before use in
    a customer's production deployment process.

See the README in the ContentRefresh PowerShell directory for
configuration, manifests, safeguards, and CI/CD usage.

## Typical workflows

**Learning or troubleshooting the APIs**

``` text
ContentRefresh / Postman
        ↓
Content Transfer API
        ↓
RAIF
        ↓
Item Transfer API
```

**Automated SitecoreAI environment refresh**

``` text
SitecoreAI PROD
        ↓
ContentRefresh / PowerShell
        ↓
SitecoreAI UAT or DEV
```

**Legacy XM/XP package migration**

``` text
Sitecore Package Designer ZIP
        ↓
PackageToRaif
        ↓
RAIF
        ↓
InspectRaif (optional QA)
        ↓
Item Transfer API
        ↓
SitecoreAI destination
```

## Important Sitecore transfer considerations

Sitecore's current guidance requires Organization Admin or Organization
Owner permissions for the Content Transfer and Item Transfer APIs.
Environment automation credentials are used to obtain JWTs for API
access.

For SitecoreAI-to-SitecoreAI transfers, prefer the Content Transfer API
for moving content between environments. Direct Item Transfer upload of
a local RAIF is intended for smaller/ad hoc transfers and is subject to
the limits documented by Sitecore.

Transferred content must also have a valid parent chain in the
destination. An item can transfer successfully but remain absent from
the content tree if its required parents do not exist with matching item
IDs. Define transfer scopes accordingly.

Always consult the current Sitecore documentation before using these
utilities in a customer environment, as the APIs and supported migration
capabilities can evolve.
